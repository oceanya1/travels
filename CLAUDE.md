Постоянный проект для планирования каждой новой поездки. Пишем по-русски.

## Где что лежит
- Этот репозиторий — главное место для правил, шаблонов и заметок по поездкам:
  - `templates/trip-template.xlsx` — шаблон поездки (вкладки: Обзор, Маршрут, Бюджет, Брони, Места и еда, Документы). `templates/build_trip_template.py` пересобирает его.
  - `templates/packing-list.md` — базовый список вещей: «Всегда» + блоки по типу поездки (море, зима, заграница).
  - `<страна>-<год>/` — папка на каждую поездку (например, `korea-2027/`), в ней `README.md` со статусом и заметками.

- Списки вещей Аня ведёт в Google Keep и отмечает там галочки. У каждого свой список: «Одежда», «Гигиена», «Документы», «Электроника», «Аптечка», «Другое».

## Как планируем поездку
1. Заводим папку `<страна>-<год>/` с `README.md`. Копируем шаблон-таблицу в Drive и называем «<Страна> <месяц год>», ссылку пишем в README.
2. Перед маршрутом сначала задаём вопросы: даты, длительность, город вылета, бюджет, темп, интересы, что уже забронировано.
3. Заполняем вкладки таблицы: маршрут по дням, бюджет (план и факт, в рублях и местной валюте), брони, места и еда, документы.
4. Для заграницы обязательно проверяем: въезд для граждан РФ, работу карт (российские карты за рубежом обычно не работают), страховку. Для Саши в документах всегда военный билет.
5. Список вещей: берём `templates/packing-list.md` и нужные блоки, переносим в Google Keep.
6. По желанию делаем интерактивную страницу поездки для телефона.

## Технические правила для Claude (чтобы не терять правки)
Аня разрешила Claude самому вливать свои PR. Ветка по умолчанию — `claude/project-thread-12sm44` (дальше «основная»).

**Перед работой**
- Клонировать или обновить репозиторий: `git fetch origin`, начинать новую ветку от свежей `origin/<основная>`.
- Если клон неглубокий и `origin/<ветка>` не находится, добавить refspec: `git config --add remote.origin.fetch '+refs/heads/<ветка>:refs/remotes/origin/<ветка>'`.
- Одна задача = одна ветка = один PR. Имя ветки по смыслу: `korea-2027-route`, `templates-budget` и т. п.

**Во время работы**
- В чужих папках поездок и в чужих ветках не менять ничего без просьбы Ани.
- Общие файлы (`CLAUDE.md`, `templates/`) править точечно, не переписывать целиком: в них могут быть правки других тредов.
- Никогда: `git push --force` в основную ветку, `git reset --hard` поверх чужих коммитов, удаление чужих файлов, rebase чужих веток.

**Перед вливанием PR**
1. `git fetch origin` и влить свежую основную в свою ветку (`git merge origin/<основная>`), а не наоборот.
2. Конфликт решать, сохраняя обе стороны. Если непонятно, чья правка верная, — не вливать и спросить Аню.
3. Проверить `git diff origin/<основная>...HEAD`: в диффе только свои изменения, ничего чужого не удалено.
4. Запушить ветку, дождаться, что GitHub показывает PR без конфликтов (`mergeable_state: clean`), и вливать обычным merge-коммитом (не squash, не rebase), чтобы история сохранялась.
5. После вливания удалить свою ветку и сообщить в треды, которые от этого зависят.

**Google Drive и Таблицы**

- Ничего не отправлять в корзину без просьбы Ани. Новая поездка = копия шаблона, сам шаблон не заполнять.
- Если правишь структуру шаблона, обнови и `templates/trip-template.xlsx` со скриптом, и таблицу в Drive, чтобы они совпадали.

**Файлы**
